# 세이브 포인트 만들기 (Git Commit)

터미널은 전혀 쓰지 않습니다. VS Code 왼쪽 사이드바의 **Source Control 패널** 버튼만 클릭합니다.

## 게임 세이브 비유

작업하던 게임을 생각해보세요.

- 게임을 하다가 어려운 구간 직전에 **저장**해두면, 실패해도 그 지점으로 돌아갈 수 있습니다.
- Figma/코드 작업도 똑같습니다. **뭔가 잘 됐을 때 "세이브 포인트"를 남기면**, 나중에 실수로 망가뜨려도 그 시점으로 되돌릴 수 있습니다.
- 이 "세이브 포인트"의 정식 이름이 **커밋(commit)** 입니다.

세이브 파일을 안 만들고 계속 진행하다가 캐릭터가 죽으면? 처음부터 다시 해야 합니다. 커밋도 마찬가지예요.

## 나중에 보게 될 단어들

지금 당장 몰라도 됩니다. 화면에 보이면 이 정도로만 이해하세요.

| 단어 | 한 줄 설명 |
|---|---|
| **브랜치 (branch)** | 같은 게임의 "다른 세이브 슬롯"이라고 생각하면 됩니다. 지금은 만들지도, 바꾸지도 마세요. |
| **머지 (merge)** | 서로 다른 슬롯의 진행 상황을 하나로 합치는 것. 개발자가 처리합니다. |
| **원격 (remote)** | 내 컴퓨터 밖, 즉 온라인(GitHub 등)에 있는 저장소. "Sync"가 여기로 보내는 버튼입니다. |

지금 단계에서는 이 세 단어를 직접 다룰 일이 없습니다. 화면에 보이면 무시하고 넘어가세요.

## 시작하기 전에: Initialize Repository

이 프로젝트 폴더에서 처음 작업한다면, Source Control 패널에 **"Initialize Repository"** 버튼이 보일 수 있습니다.

- 이건 "이 폴더의 세이브 기능을 켠다"는 뜻입니다. 한 번만 누르면 됩니다.
- 이미 버튼이 안 보이고 파일 목록이 바로 보인다면, 이미 켜져 있는 것이니 건너뛰세요.

## 세이브 포인트 만드는 순서

1. **왼쪽 사이드바에서 Source Control 아이콘 클릭** (가지 세 개가 갈라진 모양 아이콘)
2. **바뀐 파일 목록 확인 (review changes)**
   - "Changes" 아래에 파일들이 보입니다. 이게 지금까지 내가 고친 것들입니다.
   - 파일 이름을 클릭하면 뭐가 바뀌었는지 비교 화면(빨강=지운 것, 초록=추가한 것)으로 볼 수 있습니다.
   - 방금 실수로 건드린 파일이 껴 있다면, 저장하기 전에 지금 확인하세요.
3. **메시지 입력창에 짧은 설명 쓰기**
   - 위쪽 입력창에 무엇을 했는지 한 줄로 씁니다.
   - 예: `홈 화면 카드 색상 파란색으로 변경`, `상품 카드 컴포넌트 이름 정리`
   - 나중에 봐도 알아볼 수 있게, 구체적으로 쓰세요. `수정`, `업데이트` 같은 말만 쓰면 나중에 어떤 저장인지 알 수 없습니다.
4. **✓ Commit 버튼 클릭**
   - 이제 이 시점이 "세이브 포인트"로 남았습니다. 내 컴퓨터 안에 저장된 상태입니다.
5. **Sync 버튼 클릭 (선택이지만 권장)**
   - Commit 옆이나 아래에 화살표가 도는 모양의 **Sync** 버튼이 있습니다.
   - 이건 내 컴퓨터의 세이브 포인트를 온라인(팀이 같이 보는 곳)으로 올리는 버튼입니다.
   - 이걸 눌러야 다른 사람도, 그리고 내가 다른 컴퓨터에서도 이 세이브 포인트를 볼 수 있습니다.

## 황금 규칙

> **"됐다!" 싶은 순간마다 세이브 포인트를 만드세요.**

작업이 잘 되고 있을 때, 큰 부분을 끝냈을 때마다 습관처럼 Commit 하세요. 다음 시도가 잘못돼도 방금 세이브 포인트로 돌아가면 그만입니다. 하루가 끝날 때 한 번만 저장하는 건 너무 늦습니다.

## 되돌리기 (실수했을 때)

### 아직 커밋 전 — 방금 고친 걸 취소하고 싶을 때

Source Control 패널에서 파일에 마우스를 올리면 **되돌리기 화살표(Discard Changes)** 아이콘이 보입니다.

- 클릭하면 → `마지막 세이브 포인트 이후의 변경사항을 버립니다. 계속하시겠습니까?` 같은 확인 창이 뜹니다.
- "예"를 누르면 그 파일은 마지막 세이브 포인트 상태로 완전히 되돌아갑니다. **이 작업은 취소할 수 없습니다.**

### 예전 세이브 포인트로 돌아가고 싶을 때

파일을 열고 **Timeline** 패널(탐색기 하단, 파일별 히스토리)을 봅니다.

- 원하는 시점(커밋)을 찾아 클릭하면 그때의 파일 내용을 볼 수 있습니다.
- 그 파일에서 마우스 오른쪽 버튼 → **"Restore Contents"** 를 누르면, 지금 파일이 그 시점의 내용으로 바뀝니다.
- 이후 다시 Commit을 눌러야 이 되돌리기 자체도 새 세이브 포인트로 남습니다.

## Commands Used: 버튼 → 실제 명령어 대응표

개발자와 소통할 때 참고하세요. 디자이너는 왼쪽 버튼만 누르면 됩니다.

| 누르는 버튼 | 실제로 실행되는 명령어 | 의미 |
|---|---|---|
| Initialize Repository | `git init` | 이 폴더에 세이브 기능 켜기 |
| 파일이 Changes에 뜨는 것 / Commit 시 자동 포함 | `git add` | 이번 세이브에 포함할 파일 담기 |
| Commit (✓) | `git commit` | 세이브 포인트 만들기 |
| Sync / Push | `git push` | 세이브 포인트를 온라인으로 올리기 |

## 흔히 하는 실수 방지하기

- **메시지 없이 Commit 누르지 않기.** 입력창이 비어 있으면 버튼이 흐리게 표시되거나 안 눌립니다. 한 줄이라도 꼭 씁니다.
- **관계없는 파일을 같이 커밋하지 않기.** 커밋 전 파일 목록을 한 번 훑어보고, 실수로 건드린 파일이나 임시 파일이 껴 있으면 체크를 해제하거나 먼저 처리합니다.
- **"Discard Changes"는 되돌릴 수 없습니다.** 확인 창이 뜨면 습관적으로 "예"를 누르지 말고, 정말 이 변경을 버려도 되는지 한 번 더 확인합니다.
- **한 번에 너무 많은 걸 하고 커밋을 미루지 않기.** 작업 단위가 커질수록 "뭐가 바뀐 건지" 리뷰하기 어려워지고, 문제가 생겼을 때 어디서부터 되돌려야 할지도 알기 어려워집니다. 작게, 자주 세이브하세요.
- **브랜치 이름이나 Sync 관련 팝업이 낯설게 뜨면 임의로 아무 버튼이나 누르지 않기.** 모르는 팝업이 뜨면 개발자에게 스크린샷을 보내고 물어보세요.
